# Seri Iskandar Weather Intelligence (TFB2093) — Neon PostgreSQL Edition

## What this does
- Collects current Open-Meteo model-based weather estimates and immutable 24-hour-ahead forecasts for Seri Iskandar (approximate coordinates: 4.36°N, 100.96°E).
- Saves records in **Neon PostgreSQL**, with one pair of records per hourly key (first successful write wins).
- Uses GitHub Actions for unattended collection, and Streamlit for a hosted dashboard with charting, MAE/RMSE, rain-watch indication, and CSV exports.

**Architecture:** Open-Meteo → GitHub Actions (Python `collector.py`) → Neon PostgreSQL → Streamlit (`app.py`).

## First-time setup (beginner-friendly)
1. Create a **new dedicated project** in https://console.neon.tech/ (don't use another app's database).
2. In Neon **SQL Editor**, paste and execute the complete `schema.sql` file. Use a **direct/unpooled** database connection for SQL migrations if using an external migration tool.
3. From Neon project **Connect** dialog, copy the **pooled PostgreSQL connection string**, beginning `postgresql://` and containing `sslmode=require`. Keep the full URL private. If your password contains special characters, use the URL exactly as Neon supplies it.
4. Create a GitHub repository and upload this project, including the hidden `.github/workflows/collect.yml` file. **Never upload a database URL into source code.**
5. Open GitHub repository **Settings → Secrets and variables → Actions → New repository secret**. Name: `DATABASE_URL`. Value: your complete Neon **pooled** connection URL.
6. GitHub repository **Actions → Collect Seri Iskandar weather → Run workflow**. Verify it finishes successfully, then in Neon SQL Editor check:
   ```sql
   SELECT * FROM observations ORDER BY id DESC LIMIT 5;
   SELECT * FROM forecasts ORDER BY id DESC LIMIT 5;
   ```
7. Deploy your GitHub repository at https://share.streamlit.io/, with `app.py` as the entrypoint. In Streamlit **Advanced settings → Secrets**, paste:
   ```toml
   DATABASE_URL = "postgresql://YOUR_USER:YOUR_PASSWORD@YOUR-NEON-POOLER-HOST/YOUR_DB?sslmode=require"
   ```
   Replace the entire placeholder with the actual copied URL. Streamlit executes on its server; the URL stays in Streamlit's private secrets, not on the webpage. Do not add it to a public `.streamlit/secrets.toml`.
8. Open the public dashboard URL and use **Refresh saved data**. The app queries the database when the cache expires (120 seconds) or a viewer refreshes, not by automatic browser-side push.
9. Let GitHub Actions run for **72 hours or more** (4 days recommended). Every hour has two scheduled attempts; jobs can be delayed or skipped, so inspect the actual recorded time span and gaps.
10. Download `observations.csv`, `forecasts.csv`, and, after forecasts mature, `comparisons.csv`. Capture the Neon database screenshots, GitHub workflow run history, charts, accuracy scores, dates, architecture, and dashboard URL for the team's report.

## Verification queries (Neon SQL Editor)
```sql
SELECT COUNT(*) AS observation_rows, MIN(observed_hour) AS first_hour,
       MAX(observed_hour) AS last_hour FROM observations;
SELECT COUNT(*) AS forecast_rows FROM forecasts;
SELECT date_trunc('hour', observed_hour AT TIME ZONE 'Asia/Kuala_Lumpur') AS myt_hour,
       temperature_c, humidity_pct, precipitation_mm, wind_speed_kmh
FROM observations ORDER BY observed_hour DESC LIMIT 10;
```

## Important scientific limitations
- Open-Meteo **current** fields are model-derived estimates, not independent measured ground truth. Name the comparison accordingly.
- A forecast captured at ~10:17 MYT predicts the 10:00 MYT hour tomorrow, then is matched to a current estimate captured tomorrow at ~10:17, so comparisons have some timing uncertainty.
- MAE/RMSE are calculated for matched temperature, humidity, and wind speed. Rain forecast and current precipitation may refer to different accumulation intervals, so avoid claiming directly comparable rainfall MAE.
- The shown coordinates are approximate; document and verify your selected location.
- GitHub schedules are not guaranteed to run exactly on time. Neon free resources and other free platforms have quotas and restrictions; review actual plan limits before collection.
- DATABASE_URL grants database access: never publish it in Git, Streamlit frontend code, logs, reports or screenshots. For a production deployment, create a limited read-only Postgres role for the dashboard rather than using the main owner credentials.
